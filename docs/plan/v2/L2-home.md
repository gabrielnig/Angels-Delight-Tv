# L2 plan: Home hero, rows and sections (module M41)

Status: planning only, no feature code. Base: origin/main at 08d6e86. Evidence: `docs/audits/2026-11-24-netflix-rea-audit.md` sections 2 to 4 and 6, and the code paths named below. Owner wants for Home: a trailer style hero carousel (still first, optional muted preview clip), real category rows with launch defaults, admin created and named sections with a View all link each, and a hero that never sits empty.

Contents: 1 Scope, 2 Findings from the code and UI review, 3 Resolution of the auto rotate mismatch, 4 Design in brief (data, worker, config), 5 Build list (slices), 6 Stories (M41 plus exact edits), 7 Mockups S90 to S99, 8 Decisions to log, 9 Risks and dependencies, 10 Owner questions.

## 1. Scope

In scope:
- Hero: carousel of up to 5 slides, about 10 s each, auto advance, pause control, dots, previous and next, swipe, reduced motion and Data saver respected, crossfade, still image always first.
- Optional muted preview clip per slide, only on fast connections with Data saver off, generated by the worker from the video, with admin override (auto, pick a segment, off) and a fallback to the poster.
- Fix: no hero titles configured must still show a rotating hero from the newest titles. Fix: the live hero currently never draws its artwork (finding F01).
- Rows: New, Trending (Most watched), one per category, Series, Continue learning, My List, custom manual and series rows. Launch defaults seeded by the apply tool.
- Sections admin: create, name, rename, delete, reorder (drag and keyboard), per section View all link (custom URL or automatic to a category, series or full list page), minimum items, kids visibility.
- `/browse` list pages that View all needs.
- Netflix parity details from the audit: row arrows on hover for mouse only, fractional columns so the next card peeks, hover card after 300 ms on hover capable devices only, View all revealed on row hover, native scroll snap rows.

Out of scope (other lanes or later): personalisation rows, row hover videos, Top 10 numerals, TV layout, My List page changes, guest access plumbing (audit section 5, another lane owns `requireProfile` replacement), profile avatar tile focus ring (`.ad-tile:focus-visible`, audit section 4, belongs to the profiles lane), title page and player.

Module: new module M41 "Home hero, rows and sections" (viewer plus admin). It owns the behaviour M05 (viewer Home) and M17 (curation) describe in part; those stories stay and are edited, M41 adds the new behaviour. Dependencies: M04 catalog, M05, M17, M22 storage and CDN, M25 data saver, M29 site configuration, M30 job queue, M35 kids mode, M36 artwork, M16 content management (video editor).

## 3. Resolution of the auto rotate mismatch

Recommendation: auto rotate is ON by default at 10 seconds, controlled by one site setting, with a visible pause control, hold on hover and focus, no rotation under reduced motion, no rotation under Data saver, and a stop after two full loops.

Why:
1. The owner asked for about 10 s auto advance. That decision outranks the older doc default.
2. The doc default (off) was written to avoid data cost and motion sickness. A still image rotation costs one extra image per slide, lazy loaded, and Data saver already turns rotation off. Motion risk is handled by reduced motion and a pause control, which also satisfies WCAG 2.2.2 (pause, stop or hide for anything that moves for more than 5 s).
3. Code and settings disagree today (on at 8 s versus off at 7 s unused). One source of truth removes that: `features.autoplay_hero` becomes the on switch (default true, description "Hero slides change by themselves"), and a new `home.hero_interval_seconds` (default 10, range 5 to 20) sets the time.
4. 10 s beats 7 or 8 s because a title, a one line description and a clip need time to be read and seen, and Netflix style billboards sit longer than carousels on shops.
5. Stopping after two loops (`home.hero_max_loops`, 0 means never stop) keeps an idle tab from loading clips forever and gives the viewer a calm page.
6. Existing deployments: the registry default change affects only sites that never saved the key. The apply tool does not set it. Docs to edit: DESIGN-SYSTEM 8 and 11.7, M05-S01, M25-S03.

## 4. Design in brief

### 4.1 Hero behaviour

- Slide: still image first (art directed `<picture>`: 4:5 under 960 px, 16:9 from 960 px), title, meta, one line description, Play or Continue (with time left), More info. First slide image `fetchpriority="high"`, others lazy and only the next slide is prefetched when the current slide has been visible 2 s.
- Timer: one timeout per slide, started when the slide image has loaded (or after 1.5 s, whichever first), cleared and restarted on any manual change. Paused by: Pause button, hover, focus inside the carousel, tab hidden, reduced motion (never starts), Data saver (never starts), `maxLoops` reached. The Pause button stays visible in all states where rotation could run; under reduced motion and Data saver it is not rendered and a short note is not needed (nothing moves).
- Dots: 44 px hit area, current dot shows a progress fill over the slide time (transform scaleX only), the fill stops when paused. Previous and next buttons from 960 px.
- Crossfade 350 ms (`--motion-slow`), opacity only, none under reduced motion.
- A11y: `section` with `aria-roledescription="carousel"`, `aria-live="off"` while rotating and `"polite"` when paused or focused, each slide `role="group"` "n of N". One heading per slide stays h2.
- Slides: 1 slide hides all carousel controls. Fallback: when no hero titles are live, the 5 newest live titles that have artwork (config `home.hero_fallback_count`, default 5).

### 4.2 Preview clip (optional layer on a slide)

- Eligibility (all true, checked client side, re evaluated on connection change): site switch `home.hero_previews` on, clip exists (`previewUrl` present), Data saver off (`useDataSaver`), `classifyConnection()` is `fast` (existing helper in `apps/web/src/lib/lowdata/connection.ts`) and `downlink >= 5` Mbps, `prefers-reduced-motion` not reduce, tab visible, slide is the active one, carousel not paused, still image loaded. Unknown connection (Safari, Firefox have no Network Information API) is NOT eligible by default (`home.hero_previews_unknown_connection`, default false), because a wrong guess costs a Lagos viewer data.
- Sequence on an eligible slide: still shows; at 1.2 s the `<video>` gets its `src` (`preload="none"` until then), on `playing` it fades in over 350 ms; plays 6 s without sound; at the end it fades back to the still (no loop). Any `error`, `stalled` for 2 s or `abort` removes the source and leaves the still. Never preloaded for non active slides. The clip never delays the rotation timer.
- Pause button pauses the clip too; a slide change unloads the clip. The clip is decorative: `aria-hidden`, no controls, no audio track at all (encoded with `-an`), so no mute toggle is needed.
- Row cards never play video (audit: skip row hover videos).
- Budget: each clip at most 800 KB, one clip request per visible slide, immutable cache headers so loop two replays from cache.

### 4.3 Worker job `video.preview`

- Queue `video.preview` (add to `QUEUES` and `QUEUE_DEFINITIONS` in `packages/queue/src/definitions.ts`): concurrency 1, retryLimit 2, retryDelaySeconds 60, backoff, expireInSeconds 600. Payload `{ videoId, mode?: 'auto' | 'picked', startMs?: number }`.
- Triggered: (a) at the end of `pipeline.thumbnails()` success (same place sprites are made), (b) admin Recut action, (c) hourly sweep in `apps/worker/src/maintenance.ts` that enqueues up to 10 published videos with `preview_state = 'none'` (backfills the existing catalog).
- Length: 6 s (`PREVIEW_CLIP_MS = 6000`). Videos from 3 s to 8 s use the whole video; under 3 s are `skipped`.
- Auto segment: candidate starts at 20, 35, 50, 65 and 80 percent of the duration minus 3 s, clamped to `[1 s, duration - 6.5 s]`. Score a frame at start plus 3 s with the existing poster scorer (`scoreOrNull`, `LOW_FRAME_SCORE` in the pipeline); best score wins, ties go nearest the middle. Best score under `LOW_FRAME_SCORE` means `skipped` (poster fallback). This reuses code and needs no new dependency.
- Encoding (H.264 so every phone plays it, one rendition): `-ss start -t 6 -i source -an -vf scale=854:-2:flags=lanczos,fps=24,format=yuv420p -c:v libx264 -profile:v main -level 3.1 -preset slow -crf 27 -maxrate 900k -bufsize 1800k -g 48 -keyint_min 48 -sc_threshold 0 -movflags +faststart -map_metadata -1`. Expected size 500 to 700 KB. If over `PREVIEW_MAX_BYTES` (800000) retry once at crf 31, then `failed`.
- Storage key: `cap/{mediaPrefix}/preview/{startMs}-{sha8}.mp4` in the media bucket, same public cacheable prefix and `SEGMENT_CACHE` header as the sprite sheets (`makeSprites`). Content hashed so the URL is immutable. A recut writes a new key, updates the row, then deletes the old key. Slice 9 step 0 confirms the `cap/` prefix is public and not signed; if it is signed, the Home DTO carries a signed URL instead.
- Failure never fails the video: state `failed` plus a warning log, the hero falls back to the poster. Source is read with the same `fetchSource` helper as thumbnails, so the original must still exist; a missing original sets `skipped` with reason.
- Series slide: uses the clip of the episode Play would start for a new viewer (first episode), resolved in the catalog, not per viewer.

### 4.6 Row and section model

- Row kinds after change: hero, curated (manual or one series), category, recently_added (New), popular (Trending), continue_watching, my_list, each_category (a row for every visible category with at least `min_items` live titles, capped at `autoCategoryMax`, skipping categories that already have their own row), all_series (a row of series cards, hidden under `min_items` series).
- Admin row types (labels): Manual list, Category, New, Trending (most watched), Series (one series), Each category (automatic), All series (automatic), Continue learning, My List.
- View all targets in auto mode: New `/browse/new`; Trending `/browse/trending`; Category `/browse/{slug}`; Series row `/series/{slug}`; Manual `/browse/row/{slug}`; Each category, per generated row `/browse/{slug}`; All series `/browse/series`; My List `/my-list`; Continue learning none. Auto mode always shows the link when a target exists. Custom mode takes a relative path or https URL, https opens with `rel="noopener noreferrer"` and an external mark. None hides it.
- List pages (Next routes under `apps/web/src/app/(viewer)/browse/`): `new/page.tsx` (newest first, paginated, length filter), `trending/page.tsx` (top 50 by `trendingWindowDays`, no sort, empty state "Nothing is trending yet. See what is new."), `series/page.tsx` (series cards, newest first), `row/[slug]/page.tsx` (editor order, max `max_items`), existing `[categorySlug]`. Static segments win over the dynamic one, and the reserved slugs are rejected for categories. Unknown or hidden rows give the normal not found page; a kids profile gets not found for rows that are not kids visible.

## 9. Risks and dependencies

- Worker CPU on a small VPS: a 6 s encode at preset slow is a few seconds; concurrency 1 and niceness 10 keep encoding of real videos ahead. Mitigation: sweep batch of 10 per hour and a lower priority queue.
- Storage and bandwidth: about 0.6 MB per clip, one per visible slide, cached immutable. The Cloudflare free plan budget (audit section 5, about 1,200 plays a day) is not touched by 6 s clips of 5 slides unless traffic is high; the site switch turns clips off globally.
- Clip prefix visibility: assumes `cap/` is public like sprite sheets. Slice 9 step 0 verifies with a test against the storage factory and edge Worker rules; if signed, use signed URLs with the playback TTL rules.
- Original retention: preview recut needs the original. If a future retention policy deletes originals, recut falls back to `skipped` with a note and the admin sees it.
- Unknown connection policy hides clips from Safari and Firefox viewers by default. Acceptable cost, switchable.
- Reduced motion and WCAG 2.2.2: covered by pause, hold and the stop after two loops; screen reader test needed on the carousel live region.
- Enum migration: `ALTER TYPE ... ADD VALUE` is not transactional with use; separate migration file, and the Drizzle journal entry must be added by hand if the generator does not.
- Shared file collisions: `packages/ui/src/components.css`, `tokens.css`, `settings-registry.ts`, `packages/viewer/src/home.ts`, `packages/launch/src/apply.ts`, `docs/DECISIONS.md` are touched by other lanes. Keep PRs small, rebase often, resolve DECISIONS by keeping both.
- Guest access lane replaces `requireProfile` on Home and Browse; list pages must use the viewer or guest helper that exists when slice 6 starts. Guests must see the same hero and rows with the general audience.
- Migration numbers may be taken by other lanes: use the next free numbers when building.
- Two admin implementations (fixtures and real) can drift: parity test in slice 5.
- Hover card portal and scroll containers: scale must not be clipped by the row's `overflow-x` (a portal anchored to the card rect avoids it) and must follow scroll and resize; covered by tests and S96.
- Content quality: a fallback hero of the newest titles shows whatever was uploaded last; titles without good artwork sort last, but editors should still pick heroes. The launch runbook gets a line for this.
- Data budget regression: add a Home payload test (M05 performance, under 40 KB gzip for the first 3 rows) after the hero DTO gains fields.
