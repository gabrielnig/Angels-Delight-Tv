# Testing Strategy

Status: design stage. Binding rules for how tests are written and run live in `docs/TDD-PROTOCOL.md`. This file covers what to test, at which level, and how much.

## 1. Priorities

Test in this order of risk. Higher items get tests before and more tests than lower ones.

1. Authorization and data isolation (IDOR, profile ownership, kids rule, roles, RLS).
2. Authentication, sessions, tokens, rate limits, crypto and key handling.
3. Upload, probe and media validation (hostile inputs).
4. Playback chain: playback token, playlist rewrite, signed URLs, key endpoint.
5. Data integrity: publish rules, scheduling, deletion and crypto-shredding, constraints.
6. Pipeline correctness: encoding ladder, caption generation, job retry and idempotency.
7. Viewer features: progress, My List, search, rows.
8. Admin features: theme, settings, curation.
9. UI behavior and accessibility.

## 2. Test types

| Type | Tool | Runs against | Location | Purpose |
|---|---|---|---|---|
| Unit | Vitest | Pure functions, no I/O | `*.test.ts` beside code | Logic: ladder, FFmpeg args, playlist rewrite, token format, contrast math, visibility rules |
| Integration | Vitest, `integration` project | Real Postgres (compose), `local` storage driver, real pg-boss when relevant | `*.int.test.ts` | Repositories, RLS, services, route handlers called in-process, migrations |
| Contract | Vitest | Zod schemas and DTOs | `packages/shared` | Request and response shapes, env parsing |
| End to end | Playwright | Full stack in compose (web, worker, Postgres, MinIO, Mailpit) | `apps/web/e2e/*.e2e.ts` | A few critical journeys on a mobile viewport and desktop |
| Media | Vitest, tagged `slow` | Real FFmpeg on a 2 second clip created at test time | `apps/worker/**/*.media.test.ts` | Encoding output is valid, aligned, encrypted |
| Security | Vitest | Real Postgres | `*.sec.test.ts` | Authorization matrix, rate limits, hostile uploads, header checks |
| Accessibility | Playwright with axe | Key pages | e2e | No serious violations, keyboard and focus on player and forms |

Test pyramid, approximate share of test count:

```
        e2e (about 5 percent)          few, slow, critical journeys
      integration and security (about 35 percent)   real database
   unit (about 60 percent)             fast, pure logic
```

Each layer tests what the layer below cannot: units cover logic, integration covers the database, RLS and wiring, e2e covers only the journeys that cross every component. Do not repeat the same assertion at three levels.

## 3. Coverage targets

Targets are floors measured with Vitest coverage on the module, run on the module only. They guide, they do not replace judgment. Branch coverage for security modules matters more than line coverage.

| Module | Lines | Branches | Notes |
|---|---|---|---|
| `packages/crypto` (hashing, field encryption, HMAC tokens, key wrap) | 95 | 90 | Tamper, wrong key, expired, rotation |
| `apps/web/src/server/auth` (sessions, signup, reset, MFA) | 95 | 90 | Includes timing equalization and no-enumeration responses |
| Authorization policies and visibility predicate | 100 | 100 | Every role and kids case |
| Rate limiting | 95 | 90 | Refill, exhaustion, concurrency |
| `packages/db` migrations and RLS | n/a | n/a | Behavioral tests, see section 5 |
| `packages/storage` | 90 | 85 | Both drivers share one contract suite |
| `packages/video` (ladder, args, playlists) | 95 | 90 | Pure functions |
| `apps/worker` handlers | 85 | 80 | Idempotency and retry paths |
| Upload services | 90 | 85 | Resume, size mismatch, abort |
| Playback and key endpoints | 95 | 90 | Token cases, published checks |
| Viewer services (progress, list, search, rows) | 85 | 80 | |
| Admin services (theme, settings, curation) | 85 | 80 | |
| React components | 70 | 60 | Behavior via Testing Library, not snapshots |
| Route glue and pages | covered by integration and e2e | | |

## 4. Fixtures and test data

- Factories in `packages/db/testing`: `makeAccount`, `makeProfile`, `makeVideo`, and so on, with explicit overrides. Defaults are valid and boring, tests state only what they care about.
- Two accounts are the minimum setup for any ownership test (`alice`, `bob`), plus one `editor` and one `admin`.
- Database isolation: one template database migrated once per run, each integration test file gets a fresh clone (or a transaction rolled back after each test when no commits are needed).
- Media fixtures are generated at test time (`ffmpeg -f lavfi -i testsrc=duration=2:size=1280x720:rate=30 -f lavfi -i sine=duration=2`). Hostile files (renamed text file as mp4, truncated mp4, huge declared size, crafted playlist) are generated by small helper functions, never committed as binaries.
- Time: tests inject a clock. No `sleep`.
- Randomness: the crypto package accepts an injected random source for deterministic token tests.
- Secrets in tests are fixed dummy values defined in the test setup, never real ones.
- Mailpit (dev compose) receives emails in e2e. Unit tests mock the SMTP transport.

## 5. Required behavioral suites

Authorization matrix (`*.sec.test.ts`, generated from the table in SECURITY.md section 5): for every route, call as anonymous, viewer, editor, admin, and as a viewer against another account's resource. Expected status and body shape are asserted. A new route without matrix coverage fails a check that compares the route list to the matrix.

RLS suite: a connection with no `app.account_id` sees zero rows in `accounts`, `profiles`, `watch_progress`, `my_list`. Account A cannot select, insert, update or delete account B rows. Admin context can read but not write profiles through the read policy. `ad_worker` cannot select from identity tables.

Kids rule suite: kids profile cannot see a non kids-safe video in rows, search, detail, direct URL (404), playback session, or key endpoint. Kids profile writes no per-profile `view_events`.

Upload suite: resume after partial parts, size mismatch aborts, wrong type rejected, quota of pending uploads, abort cleanup, magic byte mismatch rejected by probe, FFmpeg called with the protocol whitelist.

Playback suite: token tamper, wrong video, expired, rotated `kid`, unpublished video, playlist rewrite never leaks storage keys, signed URL verifier accepts valid and rejects expired or altered paths.

Shredding suite: deleting an account removes relational data, nulls tombstone columns, destroys the DEK, records `account_deletions`, and decrypting a copied ciphertext afterwards fails. Retry job is idempotent.

Job suite: handler run twice produces the same result, retry after a mid-encode failure skips finished renditions, permanent error is recorded and not retried.

Rate limit suite: bucket refill with an injected clock, concurrent requests do not exceed the limit.

Footprint guard: a test that the repo contains none of the banned characters in tracked text files (mirrors the grep in TDD-PROTOCOL.md). It runs scoped on changed files only.

## 6. End to end scope

Only journeys that cross web, database, storage and worker. Each runs on mobile (360 by 740) and desktop.

1. Sign up, receive email in Mailpit, verify, create a profile, sign in and out.
2. Password reset through email.
3. Admin uploads a short clip (multipart to MinIO), waits for encoding, approves captions, publishes, and it appears on Home.
4. Viewer plays the video: segments load, key request succeeds, captions toggle, speed and quality menus work, progress saves, Continue Watching resumes.
5. Kids profile cannot reach a non kids-safe title.
6. Interrupted upload resumes after a network drop (Playwright offline toggle).
7. Account deletion completes and login fails afterwards.
8. Admin theme edit shows live preview, publishes, and the public site uses the new variables, with a contrast warning displayed for a bad pair.

Not in e2e: every form validation message, every admin table state, cross-browser matrices beyond Chromium and WebKit (Safari behavior of native HLS is checked manually before launch on a real iPhone and on a low-end Android device).

## 7. Performance and manual checks before launch

- Lighthouse mobile on Home, Watch and Landing with throttled network. Targets: LCP under 2.5 s on a simulated slow 4G, JS on Home under 200 KB gzip, no layout shift from images (placeholders have fixed geometry).
- Playback start time on throttled 3G profile under 6 seconds at 360p.
- Load check: 200 concurrent progress writers and 50 concurrent playlist and key requests on the VPS.
- Real device pass on a low-end Android phone for the player, upload (admin on desktop), and kids profile flow.

## 8. Running tests

See TDD-PROTOCOL.md section 2 for the scoped commands. Quick reference:

```bash
docker compose up -d postgres minio mailpit          # integration and e2e dependencies
pnpm vitest run packages/crypto/src/field.test.ts
pnpm vitest run apps/web/src/server/profiles --project integration
pnpm vitest run apps/worker/src/encode/ladder.test.ts
pnpm exec playwright test apps/web/e2e/watch.e2e.ts
```

Coverage for a module only:

```bash
pnpm vitest run packages/crypto --coverage --coverage.include='packages/crypto/src/**'
```
