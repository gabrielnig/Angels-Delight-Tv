# Open Graph and share metadata audit (lane L15b, 2026-11-25)

Scope: what L6 built (`docs/lanes/L6-build.md`, `docs/plan/v2/L6-discovery.md`) against the Open Graph protocol and the public documentation of each platform. Code read: `apps/web/src/lib/seo.ts`, `lib/seo/*`, `server/seo/*`, `app/layout.tsx`, `app/og/[kind]/[slug]/route.ts`, every `generateMetadata` and `metadata` export under `apps/web/src/app`, `publicPreview` in `server/data/real-catalog.ts`.

Sources used (public documentation, summarised, not copied): the Open Graph protocol (ogp.me) including the video object types; Meta Sharing Debugger and Sharing for Webmasters (og:title, og:type, og:image, og:url, og:site_name, og:description, og:locale, image at least 600 by 315, 1200 by 630 recommended, under 8 MB, absolute https urls); X developer docs for the `summary_large_image` card (twitter:card, twitter:title, twitter:description, twitter:image, twitter:image:alt, image under 5 MB, 2:1); WhatsApp link preview behaviour as widely documented (reads og:title, og:description, og:image, needs the image under about 300 KB, a fast response, no sign in, and is conservative about redirects); Telegram link previews and Instant View (reads og tags, falls back to twitter tags); LinkedIn Post Inspector (og:title, og:image, 1200 by 627 recommended, caches for about seven days); Slack unfurling (og and twitter tags, oEmbed optional); iMessage rich links (og:title, og:image, falls back to the page title and favicon).

## Findings

Severity: H high (a platform shows a wrong or empty card, or content leaks), M medium, L low.

### Privacy and rules

- **H1. Titles above the guest maturity ceiling leak their metadata and image.** `publicPreview` calls `findTitle` with `{ kids: false }` and no `maxRank`, so the title, description and share image of a title above `maturity.guest_max_rank` are served to any crawler. The title page itself hides it from guests, the preview does not.
- **H2. Kids only titles expose full metadata.** They are noindex (R26) but still carry the real title, description and poster in og tags and in `/og/...`. A pasted link therefore shows the title in a chat app. Rule applied by this lane: kids only titles answer with the generic platform card (site name, site description, default share image) and noindex.
- **M1. Unpublished, scheduled and trashed titles** correctly give no preview (the lookup returns null, the page and the image answer 404). Covered by a new test so it stays true.

### Open Graph tags

- **H3. Series use `og:type` website.** Should be `video.tv_show`. Videos use `video.other`, correct.
- **H4. `video:duration` is written as `<meta name=...>`** (through `other`), the protocol needs `property`. Platforms ignore it. Use the `openGraph` video fields so Next writes properties. Add `video:release_date` and `video:tag` (categories).
- **H5. No og:title, og:url, og:type on the non title pages** (see table). The Facebook debugger warns on each.
- **M2. `og:locale` is hard coded `en_NG`.** It should follow the page language and list the other enabled languages as `og:locale:alternate`.
- **M3. The layout image is a bare url.** No width, height, type or alt, so Facebook fetches it before it can render the first share (the known first share blank card problem). Give every image width, height, type and alt.
- **M4. Description cut mid word.** `short()` slices at 199 characters and appends an ellipsis, which can cut a word and a Yoruba or Igbo diacritic sequence in half. No markup stripping. Replace with a word safe trimmer (160 for og and meta, 200 for twitter) that removes HTML and control characters.
- **M5. No `twitter:site`, no `twitter:image:alt`.** The alt is dropped because the images are mapped to plain urls.
- **L1. No `og:image:secure_url`** is needed (https only). Not added, by design.
- **L2. `og:video` tags are not emitted.** Correct: the media urls are signed and short lived. Kept omitted (D-389).
- **L3. Episodes have no public page of their own.** Episode urls redirect to the series page (`episodeRedirectFor`), so the series page is the share target. The builder supports `video.episode` for when a page exists.

### Share image

- **H6. The fallback is a 302 redirect** to the default image. WhatsApp and some crawlers do not follow redirects on `og:image`. The handler must answer 200 with image bytes.
- **H7. Rendered on every request.** `force-dynamic`, Satori plus sharp per hit, no stored copy. A cold crawl can pass the WhatsApp time budget and a burst of shares costs CPU. Add a stored, keyed cache (storage object or local cache dir) with `Cache-Control: public, max-age=31536000, immutable` on versioned urls.
- **H8. The `?v=` version is `publishedAt`.** It does not change when the poster, title or share settings change, so WhatsApp and Facebook keep showing the old card. The version must be a hash of every input that affects the picture.
- **M6. Colours and font are hard coded** in the renderer (`#1f6fb5` background, `sans-serif`). The overlay colours come from a neutral scrim, which is fine for contrast, but the fallback background and the badge must come from the theme (accent token read from settings), never a literal.
- **M7. Last rung of the quality ladder returns an oversize file** if even quality 30 is too big. It must step the dimensions or fail loudly, and a test must prove under 300 KB for a noisy poster.
- **M8. No custom share image, share title or share description** per title. No play badge for videos. No setting to switch the title overlay off (posters that already carry text).
- **M9. No safe area.** Cover crop from the centre only. The title zone and badge are kept inside the central 80 percent, the crop honours an optional focal point later.
- **L4. Content type is right (`image/jpeg`)**, `Content-Length` is not set explicitly, and `Vary` is absent (good).

### Verification

- **M10. No automated check of the real tags** on a running build. Added as `pnpm share:check` with a fixture self test and a CI step.

### Other

- **L5. hreflang** is a tested helper that is not wired into metadata; it waits for the locale prefix decision (L7). Left as is, the builder accepts alternates so wiring is one line.
- **L6. Watch pages** are noindex with only a title. Correct, they are not share targets (the title page is canonical).
